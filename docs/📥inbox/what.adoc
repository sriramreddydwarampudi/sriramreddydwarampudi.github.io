= AsciiDoc Roles, IDs, and Attributes Examples

== Roles
Roles allow you to apply styles or behavior to text, blocks, or elements.

.Example:
[source,asciidoc]
----
[.highlight]
This text is highlighted.
----

.Output:
[.highlight]#This text is highlighted.#

== IDs
IDs can be used to create internal links or references.

.Example:
[source,asciidoc]
----
[[custom-id]]
== Custom Section
This section has a custom ID.
----

.Output:
[[custom-id]]
== Custom Section
This section has a custom ID.

A link to this section: <<custom-id,Custom Section>>

== Attributes
Attributes are placeholders that store values for reuse.

.Example:
[source,asciidoc]
----
:project-name: MyProject

= {project-name} Documentation
----

.Output:
:project-name: MyProject

= MyProject Documentation



= Using Attributes with Multiple Values

== Assigning Multiple Values
You can define an attribute with multiple values separated by a comma.

.Example:
[source,asciidoc]
----
:colors: red, blue, green

The available colors are {colors}.
----

.Output:
:colors: red, blue, green

The available colors are red, blue, green.

== Using Multiple Values in Conditional Logic
You can use attribute values in conditional text.

.Example:
[source,asciidoc]
----
:features: dark-mode, offline-support

ifdef::features[This product supports {features}.]
----

.Output:
:features: dark-mode, offline-support

This product supports dark-mode, offline-support.

== Using Attributes in Blocks
Attributes can be applied to blocks as well.

.Example:
[source,asciidoc]
----
[options="{colors}"]
This block uses the colors {colors}.
----

.Output:
[options="red, blue, green"]
This block uses the colors red, blue, green.

Let's break it down step by step with simple examples.


---

🔹 1. ifdef (Include Content If an Attribute Exists)

If the attribute is defined, the content inside ifdef will be shown.

Example:

:toothache: yes

ifdef::toothache[]
You have a toothache.
endif::[]

 
> (output is shown)

❌ What if toothache is NOT defined?

If you remove :toothache: yes, the content inside ifdef will NOT be shown.

---

🔹 2. ifndef (Include Content If an Attribute Does NOT Exist)

If the attribute is NOT defined, the content inside ifndef will be shown.

Example:

ifndef::toothache[]
You have no toothache.
endif::[]



> (No output)




---

🔹 3. Multiple Conditions (ifdef with AND / OR)

You can check multiple attributes using:

, (OR) → Show content if at least one is defined

+ (AND) → Show content if all are defined


Example (OR: ,)

:gum_pain: yes

ifdef::gum_pain,toothache[]
sri ram is good boy
endif::[]


> Output shown because gum pain or a toothache (gum_pain defined and toothache not defined).




---

Example (AND: +)

:toothache: yes
:gum_pain: yes

ifdef::toothache+gum_pain[]
You have both a toothache and gum pain.
endif::[]

✅ Output:

> You have both a toothache and gum pain.



❌ If one attribute is missing, no output will be shown.


---

🔹 4. ifeval (Use Numbers and Comparisons)

ifeval lets you compare numbers and text like a math formula.

Example:

:pain_level: 3

ifeval::[{pain_level} >= 3]
Your pain level is high.
endif::[]

✅ Output:

> Your pain level is high.




---

🔹 5. Combining Text and Numbers in ifeval

:condition: cavity
:pain_level: 2

ifeval::["{condition}" == "cavity" AND {pain_level} > 1]
You have a cavity with moderate pain.
endif::[]

✅ Output:

> You have a cavity with moderate pain.


:is_hungry: true

ifeval::["{is_hungry}" == "true"]
Eat something.
endif::[]

ifeval::["{is_hungry}" == "false"]
You're not hungry.
endif::[]





:is_logged_in: true
:is_admin: false

ifeval::["{is_logged_in}" == "true" AND "{is_admin}" == "true"]
Welcome, admin!
endif::[]

ifeval::["{is_logged_in}" == "true" AND "{is_admin}" == "false"]
Welcome, user!
endif::[]

AsciiDoctor supports logical operations primarily using ifeval, and it provides the following five operators:

1. Equality (==)


2. Inequality (!=)


3. Greater than (>)


4. Less than (<)


5. Greater than or equal to (>=)


6. Less than or equal to (<=)



We can derive other operations using logical AND (AND), OR (OR), and NOT (! is not supported directly, but we can use ifndef or ifeval negation).


---

1️⃣ Equality (==)

Checks if two values are the same.

✅ Example:

:mode: dark

ifeval::["{mode}" == "dark"]
Dark mode is enabled.
endif::[]

✔ Output if mode = dark

> Dark mode is enabled.



❌ No output if mode is not "dark"


---

2️⃣ Inequality (!=)

Checks if two values are not the same.

✅ Example:

:theme: light

ifeval::["{theme}" != "dark"]
Dark mode is disabled.
endif::[]

✔ Output if theme = light

> Dark mode is disabled.



❌ No output if theme = dark


---

3️⃣ Greater Than (>)

Checks if the left-hand value is greater than the right-hand value.

✅ Example:

:temperature: 30

ifeval::[{temperature} > 25]
It's a hot day!
endif::[]

✔ Output if temperature = 30

> It's a hot day!



❌ No output if temperature <= 25


---

4️⃣ Less Than (<)

Checks if the left-hand value is less than the right-hand value.

✅ Example:

:score: 50

ifeval::[{score} < 60]
You need to improve your score.
endif::[]

✔ Output if score = 50

> You need to improve your score.



❌ No output if score >= 60


---

5️⃣ Greater Than or Equal To (>=)

Checks if the left-hand value is greater than or equal to the right-hand value.

✅ Example:

:age: 18

ifeval::[{age} >= 18]
You are an adult.
endif::[]

✔ Output if age = 18 or age > 18

> You are an adult.



❌ No output if age < 18


---

6️⃣ Less Than or Equal To (<=)

Checks if the left-hand value is less than or equal to the right-hand value.

✅ Example:

:stock: 5

ifeval::[{stock} <= 10]
Stock is running low!
endif::[]

✔ Output if stock = 5 or stock < 10

> Stock is running low!



❌ No output if stock > 10


---

7️⃣ Derived Operations

✅ Logical AND (AND)

Both conditions must be true.

:temperature: 35
:humidity: 80

ifeval::[{temperature} > 30 AND {humidity} > 70]
It's very hot and humid!
endif::[]

✔ Output if temperature > 30 AND humidity > 70

> It's very hot and humid!




---

✅ Logical OR (OR)

At least one condition must be true.

:has_wifi: true
:has_ethernet: false

ifeval::["{has_wifi}" == "true" OR "{has_ethernet}" == "true"]
You have internet access.
endif::[]

✔ Output if either has_wifi or has_ethernet is true

> You have internet access.




---

✅ Logical NOT (!) using ifndef

Since AsciiDoctor does not support NOT directly, use ifndef.

ifndef::is_logged_in[]
You need to log in.
endif::[]

✔ Output if is_logged_in is not set

> You need to log in.



❌ No output if is_logged_in: true


---

✅ XOR (Exclusive OR)

One condition must be true, but not both.

:light_on: true
:fan_on: false

ifeval::["{light_on}" == "true" XOR "{fan_on}" == "true"]
Only one of them is on.
endif::[]

✔ Output if light_on is true and fan_on is false

> Only one of them is on.



✔ Output if light_on is false and fan_on is true

> Only one of them is on.



❌ No output if both are true or both are false

In AsciiDoctor, you can express IF-THEN, BIDIRECTIONAL IMPLICATION, and other logic conditions using ifeval::[] and conditional attributes. Here's how you can represent these logical structures:


---

1️⃣ IF-THEN (P → Q)

Meaning: If P is true, then Q must be true.

✅ Example:

:rain: true

ifeval::["{rain}" == "true"]
Take an umbrella.
endif::[]

✔ Output if rain = true

> Take an umbrella.



❌ No output if rain = false


---

2️⃣ BIDIRECTIONAL IMPLICATION (P ↔ Q)

Meaning: P is true if and only if Q is true.

✅ Example:

:logged_in: true
:access_granted: true

ifeval::["{logged_in}" == "true" AND "{access_granted}" == "true"]
You can enter the system.
endif::[]

ifeval::["{logged_in}" == "false" AND "{access_granted}" == "false"]
You cannot enter the system.
endif::[]

✔ Output if both logged_in = true and access_granted = true

> You can enter the system.



✔ Output if both logged_in = false and access_granted = false

> You cannot enter the system.



❌ No output if one is true and the other is false

✅ Simplified way using XOR (to check mismatch):

ifeval::["{logged_in}" == "true" XOR "{access_granted}" == "true"]
There's a mismatch in login status.
endif::[]

✔ Output if one is true and the other is false

> There's a mismatch in login status.




---

3️⃣ IF-THEN-ELSE (P → Q, ¬P → R)

Meaning: If P is true, do Q; otherwise, do R.

✅ Example:

:vip_member: true

ifeval::["{vip_member}" == "true"]
You get VIP benefits.
endif::[]

ifeval::["{vip_member}" != "true"]
You get regular benefits.
endif::[]

✔ Output if vip_member = true

> You get VIP benefits.



✔ Output if vip_member = false

> You get regular benefits.




---

4️⃣ IF AND ONLY IF (IFF, P ↔ Q) Using Derived Conditions

Meaning: P is true if and only if Q is true.

✅ Example:

:open: true
:lights_on: true

ifeval::["{open}" == "{lights_on}"]
The room's state is consistent.
endif::[]

ifeval::["{open}" != "{lights_on}"]
There's an inconsistency in the room's state.
endif::[]

✔ Output if both open and lights_on are either true or false

> The room's state is consistent.



✔ Output if one is true and the other is false

> There's an inconsistency in the room's state.
